Git Professional Masterclass Reference

Comprehensive Guide to Version Control, Workflows, and Commands

1. Git Architecture: The 4 Zones

Understanding how files move between local storage and remote servers is crucial for avoiding data loss.

1. Working Directory

Your actual project files on disk. Changes here are untracked or modified until added.

2. Staging Area (Index)

A preparation buffer zone. Allows you to group specific changes into a clean single snapshot.

3. Local Repository

The hidden .git database. Holds all committed snapshots (commits) permanently on your machine.

4. Remote Repository

Cloud server (GitHub, GitLab, Bitbucket). Centralized server for team collaboration.

A. Setup & Configuration

Set identity and start new projects.

Initialize a new repository git init

Creates a hidden .git folder in the current directory.

Clone an existing project git clone <repository-url>

Downloads the remote repository and sets up local tracking branches automatically.

Global User Configuration git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Attaches your name and email address to every commit you make.

B. Staging & Committing

Tracking file state changes and saving checkpoints.

Inspect Repository Status git status

Displays untracked, modified, and staged files across your workspace.

Stage Specific or All Files git add <filename>
git add .

Moves changes from the Working Directory into the Staging Area.

Commit Staged Changes git commit -m "Descriptive message"

Saves the staged snapshot permanently into the local repository history.

View Commit History git log --oneline --graph

Shows a concise tree view of past commits and active branches.

C. Branching & Merging

Isolate changes and experiment safely without breaking production code.

List All Branches git branch -a

Shows local and remote branches. Current branch is highlighted with an asterisk (*).

Create & Switch Branch git switch -c feature-name
git checkout -b feature-name

Creates a new branch and switches your workspace to it immediately.

Merge Branch into Current git merge feature-name

Combines commits from feature-name into your currently active branch.

Delete a Feature Branch git branch -d feature-name

Deletes the branch safely after it has been merged.

D. Remote Synchronization

Share code with teams and synchronize with online platforms like GitHub.

Link Local to Remote git remote add origin <url>

Assigns remote URL to the alias name 'origin'.

Push Local Commits git push -u origin main

Uploads local commits. -u establishes upstream tracking for future pushes.

Fetch Remote Changes git fetch origin

Downloads new refs and commits from remote without altering your local working files.

Pull Remote Changes git pull origin main

Executes git fetch followed immediately by git merge.

E. Undoing & Reverting

How to recover from mistakes gracefully without corrupting history.

Unstage a File (Keep Edits) git restore --staged <file>

Removes file from staging area back to modified working directory.

Discard Local Uncommitted Changes git restore <file>

Irreversible: Reverts file in working directory back to last commit state.

Safely Revert a Past Commit git revert <commit-hash>

Creates a new commit that undoes changes from a previous commit safely for shared repos.

Stash Temporary Uncommitted Work git stash / git stash pop

Shelves uncommitted changes temporarily so you can switch branches cleanly.

F. The .gitignore File

Prevent sensitive files and auto-generated build outputs from being tracked.

Create a plain text file named .gitignore in root folder:

# Ignore node_modules & build directories
node_modules/
target/

# Ignore secret environment variables
.env

# Ignore OS files
.DS_Store

3. Teaching Special Scenario: Resolving Merge Conflicts

A merge conflict occurs when two developers modify the exact same line in a file on different branches and attempt to merge them together.

What Git places inside your code file during a conflict: 
<<<<<<< HEAD (Your Current Branch Changes)
System.out.println("Hello from Main!");
=======
System.out.println("Hello from Feature Branch!");
>>>>>>> feature-a (Incoming Branch Changes)

Steps to Resolve Merge Conflicts:

  • Open the conflicted file in VS Code or any text editor.
  • Choose which code snippet to keep and delete the conflict markers (<<<<<<<, =======, >>>>>>>).
  • Save the file.
  • Run git add <file> to mark the conflict as resolved.
  • Run git commit -m "Resolved merge conflict" to finalize the merge.

4. Operation Deep Dive: Fetch vs. Pull vs. Checkout vs. Switch

Command Target Area Safety Level Primary Purpose
git fetch Local Repository Database 100% Safe Downloads new updates from GitHub without altering your working code.
git pull Working Directory + Local Repo Modifies Files Fetches remote commits AND auto-merges them into your current files.
git switch Working Directory Safe Modern command dedicated solely to switching branches.
git checkout Working Directory Use with care Multi-purpose legacy tool used to switch branches OR restore past files.
